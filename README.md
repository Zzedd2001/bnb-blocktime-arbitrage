# Replication package — *Faster Blocks Fall Short of the Square-Root Law: Arbitrage Rents and Latency across Three Block-Interval Reductions on BNB Chain*

Replication package accompanying the revised manuscript (Digital Finance, revision 1, September 2026).
It contains the data pipeline, the processed data underlying every result, the estimation scripts that
produce every table and figure of the paper, and a manifest (`MANIFEST.md`) that lists, for each table and
figure, the script and the input files that generate it. The retrieval scripts read API credentials from
environment variables and none is included.

## Contents

```
replication_v6/
  README.md                       this file
  MANIFEST.md                     table/figure -> script -> inputs
  LICENSE                         MIT
  requirements.txt                Python packages (versions used)
  run_all.sh                      regenerates every v6 table and figure from the processed data (~10 min)
  check_anonymity.sh              greps the package for names, e-mail addresses, home paths and API keys
  assemble_large_data.sh          restores the arbitrage-level tables from the pipeline's archives
  dex-lit/bnb_blocktime_pilot/    data pipeline (Section 4, Appendices A and D)
  paper/                          estimation scripts, manuscript sources (paper/v6/*.md), tables_v6/, figures_v6/
  lorentz_tick/ maxwell_tick/ fermi_tick/
                                  hourly pool panels and regime tables, trade reference (Sections 4-7)
  lorentz/ maxwell/ fermi/        the same with the 1-second candle reference, and the lag-250 ms panels (Appendix C)
  tick_cmp/                       candle-versus-trade comparison of the same pool-hours (Section 6.2, Table C2)
  arb_resp/                       opening times, response times, components and operators (Sections 4.5, 6.6, 6.7, Appendix D)
```

The arbitrage-level tables (about 750 MB) are not in the git tree; they are attached as nine archives to the `v6.0` GitHub Release of this repository: for each fork
and pool, `arb_resp/<Fork>/arb_response/<pool>/arbs_sample.parquet` (all flow) and
`arb_resp/bots/<Fork>/arb_response_bots/<pool>/arbs_sample.parquet` (bot flow) — 100,000 arbitrages per pool
with opening time, trigger type, response time, block count and components — and
`arb_resp/ops/<Fork>/arb_response/operators/<pool>_arbs_tx.parquet`, the strict arbitrages of the active
contracts joined to their signing accounts and gas. Download the nine archives (`arb_response_<Fork>.zip`, `arb_response_bots_<Fork>.zip`, `arb_txfrom_<Fork>.zip`; `gh release download v6.0 --dir <dir>`) into one folder and run `bash assemble_large_data.sh <dir>` from this directory to restore the full layout.
The complete (unsampled) arbitrage-level tables, `arb_response/<pool>/arbs.parquet`, are regenerated by the
pipeline (`arb_response.py`) from the swap-level data in a few minutes per pool.

## Requirements

Python 3.11+ with the packages in `requirements.txt` (pandas, numpy, pyarrow, scipy, statsmodels, matplotlib;
`hypersync` and `requests` only for the retrieval stage). The manuscript is typeset from `paper/paper_v6.md`
with `paper/sn/md2sn.py` (Springer `sn-jnl` class, `latexmk`) and exported to Word with `paper/md2docx.js`
(Node.js, `docx` package).

```
pip install -r requirements.txt
```

## Reproducing the tables and figures (processed data -> paper)

Every script resolves its paths from `REPL_ROOT` (default: this directory). From the package root:

```
bash run_all.sh
```

runs, in order, `paper/main_spec.py` (Table 3, Table D5, `tables_v6/main_spec.json`), `paper/lp_levels.py`
(Table 4), `paper/latency_floor_v6.py` (Table 7), `paper/grid_v6.py` (Tables B1-B3), `paper/vol_competition.py`
(Table 5, Tables D2-D3), `paper/classification_table.py` (Table B5), `paper/build_figures_v6.py` (Figures 1-3,
A1-A2, B1, C1, D1-D2) and `paper/make_v6.py` (assembles `paper/paper_v6.md` from `paper/v6/*.md`, the tables and
`paper/paper_df.md`, the source of the appendix tables). The outputs are written to `paper/tables_v6/`,
`paper/figures_v6/` and `paper/paper_v6.md` and can be compared with the copies shipped in the package.
`paper/vol_competition.py` (Table 5, Tables D2-D3) reads the arbitrage-level operator tables and therefore needs the Release archives restored with `assemble_large_data.sh`; `run_all.sh` skips it otherwise and keeps the shipped outputs. `paper/sim_sigma_elasticity.py` regenerates Table D1 (it simulates five synthetic forks; about 10 minutes). `paper/did_crosschain.py` estimates the cross-chain difference-in-differences once control panels of the same pairs on another chain are placed at `<fork>_ctrl/bundle/analysis_agg/hourly_panel.parquet`; no such panels are part of this package.
To typeset: `python3 paper/sn/md2sn.py paper/paper_v6.md build && cd build && bash build.sh`.

The scripts that produced the appendix tables inherited from the first submission (`paper/three_forks.py`,
`paper/build_tables_v41.py`, `paper/build_tables_v41_bots.py`, `paper/robust_bots.py`, `paper/latency_floor.py`,
`arb_resp/compare_bots.py`, `arb_resp/ops/ops_analysis.py`, `arb_resp/pkg/full_components.py`) are included with
their outputs (`paper/three_forks_tick/`, `paper/tables_v41/`, `arb_resp/cmp_bots/`, `arb_resp/ops/out*/`,
`arb_resp/pkg/tables/`); `MANIFEST.md` maps each appendix table to them.

## Rebuilding the processed data from public sources (raw data -> processed data)

All raw data are public: BNB Chain block headers and swap events (any JSON-RPC endpoint; Envio HyperSync for the
event logs), and Binance's market-data archive (data.binance.vision: 1-second klines and aggregate trades).
`dex-lit/bnb_blocktime_pilot/README.md` documents the pipeline stage by stage. In outline, per fork:

```
cd dex-lit/bnb_blocktime_pilot
export ENVIO_API_TOKEN=<free token from envio.dev>            # event logs; or --logs-rpc <url> for eth_getLogs
python run_pilot.py --fork Fermi --hours 720 --pools all --out full_fermi --include-swaps --hypersync --workers 4 --reference aggtrades
python full_analysis.py --results full_fermi --subdir results_agg                       # -> analysis_agg/ (hourly panels, ±30 d)
python full_analysis.py --results full_fermi --subdir results_agg --days 14 --out full_fermi/analysis_agg_14d
python core_analysis.py --bundle full_fermi --label Fermi --out full_fermi/extra_agg --analysis-dir analysis_agg --analysis14-dir analysis_agg_14d --summary summary_agg.json
python arb_response.py --out full_fermi --fork Fermi                                    # opening times, response times, components
python arb_component_panel.py --out full_fermi --fork Fermi                             # hourly component panels
python fetch_tx_from.py --out full_fermi --fork Fermi                                   # signing accounts and gas of active contracts
python arb_operators.py --dir full_fermi/arb_response/operators --fork Fermi --out full_fermi/arb_response/operators/out
python arb_response.py --out full_fermi --fork Fermi --reuse --exclude-senders public_contracts_Fermi.csv   # bot flow
python arb_component_panel.py --out full_fermi --fork Fermi --tag bots
```

`--reference aggtrades` selects the trade reference (the default is the 1-second candle), `--ref-lag-ms 250`
the reference aligned 250 ms before the block. Each fork's full sample rebuilds on a laptop in a few hours; the
aggregate-trade alignment adds 6-8 GB of downloads per fork. `simulate_test.py` and `simulate_response_test.py`
run the pipeline end to end on synthetic data with known latencies (Appendix D) without network access.

The layout of the processed-data directories is the pipeline's: `<fork>_tick/bundle/` holds
`summary_agg.json`, `results_agg/` (regime tables, `blocks_hourly.csv`), `analysis_agg/` and `analysis_agg_14d/`
(`hourly_panel.parquet`, regressions, matched pairs, placebos), `extra_agg/` (core-pool estimates);
`arb_resp/comp_bots/<Fork>/arb_response_bots/component_panels/<pool>.csv` are the hourly component panels of
bot flow, and `arb_resp/cmp_bots/` the response-time statistics across regimes (`key_numbers.json`, `R4_points.csv`).
